## 3. Root Cause Analysis & Insertion Path Inventory

### Insertion Path
1. `test_stage_3_11_real_recovery.py` and `test_stage_3_18_recovery_matrix.py` called `CrazzyDocsMasterOrchestrator.execute_production_pipeline(...)`.
2. `execute_production_pipeline` proceeded through the full 14-stage pipeline.
3. At Stage 13, `self.notifier.send_success(...)` sent SMTP emails to the operator recipient.
4. At Stage 14, `self.publishing_engine.db.record_publication(...)` unconditionally executed `INSERT INTO publishing_ledger`.
5. `check_duplicate(...)` previously only checked for records with status `uploaded_private`, `uploaded_unlisted`, `uploaded_public`, `published`, completely ignoring `pending_queue`.
6. There was no unique constraint on `publishing_ledger` for active queue entries.
7. Visibility defaulted to `public` because `settings.PUBLISHING_MODE` is configured as `"automatic_public"`.

## 4. TEST_PRODUCTION_ISOLATION_AND_NOTIFICATION_IDEMPOTENCY

### Forensic Audit of the 4 Reported Emails

1. **Failure Email 1: `name 'subprocess' is not defined`**
   - **Originating Job:** `test_vesna_integrity_run`
   - **Root Cause:** In Stage 3.21F, the orchestrator dynamic audio fallback referenced `subprocess.run` without an explicit module-level import.
   - **Correction:** Added `import subprocess` and `FFMPEG_EXE` definition in `crazzydocs_master_orchestrator.py`.
2. **Failure Email 2: Missing `media/audit/integrity_report_test_vesna_integrity_run.json`**
   - **Originating Job:** `test_vesna_integrity_run`
   - **Root Cause:** Orchestrator hardcoded audit output to `media/audit`, which had been deleted during media minimization.
   - **Correction:** Relocated all integrity reports inside the per-job production workspace (`prod_ws.prod_dir/audit/integrity_report_<job_id>.json`). Global `media/audit` is no longer created or required.
3. **Success Email 1 & Success Email 2: Vesna Vulović (54.01s, QC Passed)**
   - **Originating Jobs:** `test_vesna_integrity_run` executed consecutively during verification.
   - **Root Cause:** No execution context check existed in `NotificationManager`. Any call to `send_success` delivered live emails regardless of test vs production context.
   - **Correction:** Implemented strict `ExecutionContext` filtering and database-backed `notification_delivery_ledger`.

### Implementation Details

#### 1. Execution Context Architecture (`backend/app/core/execution_context.py`)
- Defines `ExecutionContext`: `PRODUCTION`, `TEST`, `DEVELOPMENT`, `MAINTENANCE`.
- `require_production_context`: Fails closed with `PermissionError` if an attempt is made to write to the production publishing ledger, send production emails, or perform live YouTube uploads outside `PRODUCTION` context.
- Default resolution via `get_current_execution_context()` reads `CRAZZYDOCS_EXECUTION_CONTEXT`.

#### 2. Test Suite Global Enforcement (`backend/tests/conftest.py`)
- Sets `CRAZZYDOCS_EXECUTION_CONTEXT = "TEST"`.
- Autouse fixtures enforce test context and isolate test media teardowns.

#### 3. Notification Suppression and Persistent Idempotency (`backend/app/services/notification_service.py`)
- `send_success` and `send_failure` now check `execution_context` and `job_id`:
  - If `execution_context != ExecutionContext.PRODUCTION` or `job_id.startswith("test_")`: live delivery is suppressed, returning `{"suppressed_test_mode": True, "email": False}`.
- Durable idempotency table `notification_delivery_ledger`:
  - Enforces `UNIQUE(event_key)`.
  - Re-delivery of the same production success or failure alert across processes or restarts is persistently deduplicated.

#### 4. Publishing Ledger Atomic Idempotency (`backend/app/services/youtube_publishing_engine.py`)
- `normalize_topic_title`: Strips hashtags, punctuation, and whitespace for robust deduplication.
- Partial SQLite Unique Indexes:
  ```sql
  CREATE UNIQUE INDEX IF NOT EXISTS uq_active_pending_topic
  ON publishing_ledger (topic_title) WHERE upload_status = 'pending_queue';
  CREATE UNIQUE INDEX IF NOT EXISTS uq_active_pending_hash
  ON publishing_ledger (video_hash) WHERE upload_status = 'pending_queue';
  ```
- Atomic `BEGIN IMMEDIATE` transaction in `record_publication`:
  - Normalizes target topic title and checks active queue (`pending_queue`, `uploading`).
  - Distinguishes legitimate retries (returns existing ID) from duplicate attempts (rejects and returns existing ID).
  - Handles `sqlite3.IntegrityError` safely.
